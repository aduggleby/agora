# Agora API v1 (connected apps)

This is the complete contract for apps that connect to an Agora server on behalf of a user, such as the macOS capture
app. An app signs the user in through the browser (it never sees the password), receives a bearer token, and uses it
to create and delete **temporary direct links** (a single image served as raw bytes at `/s/{token}`).

Examples use `https://files.example.com` as the server. All paths are relative to the server URL the user enters
(scheme, host and optional port, no trailing slash).

## 1. Overview

| Method and path | Auth | Purpose |
| --- | --- | --- |
| `GET /connect/authorize` | browser session (sign-in page if needed) | consent page, opened in the user's browser |
| `POST /connect/authorize` | browser session + CSRF (the page's own form) | Approve or Deny; redirects to the app |
| `POST /api/v1/auth/token` | none (rate limited, PKCE) | exchange the authorization code for a token |
| `DELETE /api/v1/auth/token` | bearer | revoke the calling token (Disconnect) |
| `GET /api/v1/me` | bearer | account summary and server limits |
| `POST /api/v1/captures?duration=...` | bearer | upload one PNG or JPEG, get a temporary direct link |
| `DELETE /api/v1/shares/{token}` | bearer | delete one of the user's direct links early |

Ground rules:

- There is exactly one client: `client_id=agora-capture`. There is no client secret and no client registration.
- `/api/v1/*` accepts **only** bearer API tokens. Browser cookies are ignored there (a cookie-only request gets `401`),
  and no CSRF token is needed or checked.
- Every other endpoint of the server accepts **only** the browser session. An API token presented anywhere else is
  ignored: the request gets a JSON `401` (or `403`), never a redirect to the sign-in page.
- Requests and responses are JSON (UTF-8) except the capture upload (multipart). Timestamps are ISO 8601 in UTC
  (for example `2026-11-05T09:30:00.123Z`).
- Responses from `/api/v1/auth/token` and all `401` responses carry `Cache-Control: no-store`.

## 2. Connecting

OAuth 2.0 authorization code flow ([RFC 6749](https://www.rfc-editor.org/rfc/rfc6749)) with PKCE
([RFC 7636](https://www.rfc-editor.org/rfc/rfc7636), `S256` only) and a loopback redirect for native apps
([RFC 8252](https://www.rfc-editor.org/rfc/rfc8252)).

```
App                                   Browser                              Agora
 | listen on 127.0.0.1:<port>/callback
 | open authorize URL --------------> GET /connect/authorize?...
 |                                    (not signed in: /login, then back to the same URL)
 |                                    consent page: Approve ---------------> POST /connect/authorize
 |                                    <------------------------------------ 302 http://127.0.0.1:<port>/callback?code=..&state=..
 | <-- GET /callback?code=..&state=..
 | answer "You can close this tab", check state
 | POST /api/v1/auth/token {code, code_verifier, ...} -------------------->
 | <------------------------------------------------- 200 {access_token: "agora_pat_...", ...}
 | store the token in the Keychain
```

### 2.1 Prepare

1. Start an HTTP listener on `127.0.0.1` (or `[::1]`) on any free port from 1024 to 65535 (bind port 0 and read the
   assigned port). It serves one path, `/callback`.
2. Generate:
   - `code_verifier`: 32 random bytes from a CSPRNG, base64url without padding (43 characters). Allowed alphabet
     `A-Z a-z 0-9 - . _ ~`, length 43 to 128.
   - `code_challenge` = base64url-without-padding of SHA-256 over the ASCII bytes of `code_verifier` (always 43
     characters).
   - `state`: 16 random bytes, base64url without padding.
3. Build `redirect_uri` exactly as `http://127.0.0.1:<port>/callback` (or `http://[::1]:<port>/callback`).

### 2.2 Open the consent page

Open this URL in the user's default browser (all values percent-encoded as query parameters):

```
https://files.example.com/connect/authorize
  ?client_id=agora-capture
  &redirect_uri=http%3A%2F%2F127.0.0.1%3A53682%2Fcallback
  &state=1d2cRZy5q3cX4vH8sEw0Yw
  &code_challenge=E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM
  &code_challenge_method=S256
  &device_name=AgoraCapture%20on%20Alex%27s%20MacBook
```

| Parameter | Required | Rule |
| --- | --- | --- |
| `client_id` | yes | exactly `agora-capture` |
| `redirect_uri` | yes | exactly `http://127.0.0.1:<port>/callback` or `http://[::1]:<port>/callback`, port 1024-65535 written without leading zeros. No other host (`localhost` is rejected), scheme, path, user info, query or fragment. |
| `state` | yes | 1 to 512 printable ASCII characters (`0x20`-`0x7E`); returned unchanged |
| `code_challenge` | yes | 43 base64url characters (an S256 challenge) |
| `code_challenge_method` | yes | exactly `S256` |
| `device_name` | no | shown on the consent page and in the user's Settings; at most 200 characters. Control and formatting characters are removed, the rest is trimmed and cut to 100 characters; empty becomes `Unknown device`. |

Each parameter may appear at most once. The match on fixed values is case-sensitive.

If the user is not signed in, Agora shows its sign-in page and returns to the same authorize URL afterwards with all
parameters intact. (If the sign-in takes a detour, such as an unconfirmed email address, the user may have to start the
connection again from the app.)

The page shows the device name, the signed-in email, what the app will be able to do, and **Approve** / **Deny**.

### 2.3 What comes back to the callback

The browser is redirected (`302`) to `redirect_uri` with a query string. Values are percent-encoded; decode them with a
standard URL parser.

| Outcome | Callback query |
| --- | --- |
| Approved | `?code=<code>&state=<state>` |
| Denied (or the account can no longer consent, for example it was disabled) | `?error=access_denied&state=<state>` |
| Any parameter other than `redirect_uri` invalid or missing | `?error=invalid_request&state=<state>` (`state` is omitted when it was itself missing or invalid) |

If `redirect_uri` is missing or invalid, Agora **never redirects**: the page shows an error (`400`) and the app's
listener receives nothing. Apps should therefore time out the listener (for example after 5 minutes) and tell the
user to try again.

The app must:

- accept only `GET /callback` and answer it with a small HTML page ("You can close this tab");
- compare `state` with the value it generated and ignore the callback on a mismatch;
- treat `error=access_denied` as "the user declined" and `error=invalid_request` as a client bug;
- stop listening after the first valid callback.

The authorization code is 43 base64url characters, valid for **10 minutes**, and single use.

## 3. Token endpoint

### `POST /api/v1/auth/token`

Exchanges the authorization code for a token. Anonymous; rate limited per client IP (10 requests per minute shared
with the sign-in endpoints). Body at most 16 KB.

Request:

```
POST /api/v1/auth/token
Content-Type: application/json

{
  "grant_type": "authorization_code",
  "code": "<code from the callback>",
  "code_verifier": "<the verifier from 2.1>",
  "redirect_uri": "http://127.0.0.1:53682/callback",
  "client_id": "agora-capture"
}
```

`redirect_uri` must equal the value sent to `/connect/authorize` byte for byte.

`200 OK`:

```json
{
  "access_token": "agora_pat_q0S1f8lYQ2l1o8i3iN0eZx7f3d4kW0a9b8c7d6e5f4g",
  "token_type": "Bearer",
  "token_id": "6f1c1f43-6a5e-4a3e-9d43-2a6f0f9d1c11",
  "email": "alex@example.com"
}
```

The token is shown **only in this response**; the server keeps only its SHA-256 hash.

Errors are `400` with an RFC 6749 style body:

```json
{ "error": "invalid_grant", "error_description": "The authorization code is invalid, expired or already used, or does not match this request." }
```

| `error` | When |
| --- | --- |
| `invalid_request` | body is not `application/json`, not valid JSON or too large; `grant_type`, `code`, `code_verifier`, `redirect_uri` or `client_id` missing; unknown `client_id` |
| `unsupported_grant_type` | `grant_type` is not `authorization_code` |
| `invalid_grant` | code unknown, expired, already used, or issued for a different `redirect_uri`/`client_id`; `code_verifier` does not match the challenge; the user was disabled or changed credentials since consent |

Requests rejected with `invalid_request` or `unsupported_grant_type` (unreadable body, missing parameter, unknown
`client_id`, wrong `grant_type`) are refused before the code is looked at, so the code stays usable for a corrected
request within its 10 minutes. Any request that reaches the code check **burns the code whatever its outcome**: after
an `invalid_grant` it cannot be retried with the same code, and a second exchange of a code that already produced a
token gets `invalid_grant`. Start the flow again.

`429 Too Many Requests` (empty body, `Retry-After` header in seconds) when the rate limit is hit.

```sh
curl -sS https://files.example.com/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"grant_type":"authorization_code","code":"<code>","code_verifier":"<verifier>","redirect_uri":"http://127.0.0.1:53682/callback","client_id":"agora-capture"}'
```

## 4. Using the token

- Format: `agora_pat_` followed by 43 base64url characters (`A-Z a-z 0-9 - _`), 53 characters in total. Treat it as
  opaque apart from this prefix.
- Send it on every `/api/v1` call: `Authorization: Bearer agora_pat_...` (the scheme word `Bearer` with this exact
  capitalization, one space).
- Store it in the macOS **Keychain** (`kSecClassGenericPassword`; the capture app uses service `agora.capture`),
  together with the server URL. Never write it to `UserDefaults`, files or logs, and never put it in a URL.
- In Agora's Settings > Connected apps the token is listed by device name and as `agora_pat_` plus its first 8
  characters after the prefix.
- Authenticated calls share the user's general rate limit (120 requests per minute per account).

## 5. Endpoints

All endpoints below require `Authorization: Bearer agora_pat_...`. Without a working token they answer `401` (see
[section 6](#6-errors-and-status-codes)).

### 5.1 `GET /api/v1/me`

Account summary and the server's limits. Call it after connecting and before showing duration choices; never
hardcode durations or size limits.

`200 OK`:

```json
{
  "email": "alex@example.com",
  "displayName": "Alex",
  "serverVersion": "0.9.27",
  "maxFileSizeBytes": 5368709120,
  "directLinkDurations": ["30m", "6h", "1d", "7d"]
}
```

| Field | Meaning |
| --- | --- |
| `email` | the account's email (lower case) |
| `displayName` | the account's display name, or the email when none is set |
| `serverVersion` | Agora's version string |
| `maxFileSizeBytes` | largest capture the server accepts (file bytes, not the multipart envelope) |
| `directLinkDurations` | the accepted `duration` values, shortest first: `30m` (30 minutes), `6h`, `1d`, `7d` |

```sh
curl -sS https://files.example.com/api/v1/me -H "Authorization: Bearer $AGORA_TOKEN"
```

### 5.2 `POST /api/v1/captures?duration=<duration>`

Uploads one image and creates a temporary direct link to it. The result is an ordinary direct link of the user: it
appears in "My shares" with the Direct link badge, counts every view, and expires and is purged like one created in
the browser.

- `duration` (query string, required): one of the `directLinkDurations` from `/me`. It is in the query string so the
  server can refuse a bad request before reading the body.
- Body: `multipart/form-data` with one part named `file`:
  - the part **must have a filename** ending in `.png`, `.jpg` or `.jpeg` (case-insensitive), and
  - the file content must start with the matching signature (PNG `89 50 4E 47 0D 0A 1A 0A`, JPEG `FF D8 FF`).
  The part's `Content-Type` is not used. Send `image/png` anyway.
- Size: the file at most `maxFileSizeBytes`; the whole request at most `maxFileSizeBytes` + 1 MB.

```
POST /api/v1/captures?duration=1d
Authorization: Bearer agora_pat_...
Content-Type: multipart/form-data; boundary=----agora

------agora
Content-Disposition: form-data; name="file"; filename="capture.png"
Content-Type: image/png

<PNG bytes>
------agora--
```

`200 OK`:

```json
{
  "url": "https://files.example.com/s/Ab3dE6gH",
  "token": "Ab3dE6gH",
  "expiresAtUtc": "2026-11-05T09:30:00.123Z"
}
```

- `url`: the public link to copy. Opening it returns the image itself (`image/png` or `image/jpeg`) until it expires,
  then `410 Gone`.
- `token`: the share token (8 letters and digits); keep it to delete the link later.
- `expiresAtUtc`: when the link stops working.

Errors (all JSON `{ "error": "<message>" }` unless noted):

| Status | When |
| --- | --- |
| `400` | `duration` missing or not one of the allowed values; body not `multipart/form-data`; no part named `file`; multipart body unreadable; not a PNG/JPEG (extension and signature must agree); other upload validation |
| `401` | missing, invalid, revoked or expired token |
| `409` | the upload was already submitted (only on an internal race; retry with a new request) |
| `413` | the image (or request) is larger than the server accepts |
| `429` | rate limited: empty body with `Retry-After` (seconds), or JSON when an account quota (open uploads, daily upload budget) is used up or two uploads of the account are already in progress |
| `503` | the link could not be created right now; retry later |
| `507` | the server's scratch space is full; retry later |

Nothing is left on the server when a capture is refused.

```sh
curl -sS "https://files.example.com/api/v1/captures?duration=1d" \
  -H "Authorization: Bearer $AGORA_TOKEN" \
  -F "file=@capture.png;type=image/png"
```

### 5.3 `DELETE /api/v1/shares/{token}`

Deletes one of the user's own **direct links** before it expires (`{token}` is the `token` from the capture
response). Afterwards its URL answers `410 Gone`.

| Status | When |
| --- | --- |
| `204 No Content` | deleted, or it was already deleted (idempotent) |
| `401` | missing, invalid, revoked or expired token (JSON `{ "error": "..." }`) |
| `404` | no such token, it belongs to someone else, or it is not a direct link (a normal share); body `{ "error": "No such direct link." }`. The cases are deliberately indistinguishable. |

An app keeping a list of recent links should drop an entry on `204` and on `404`.

```sh
curl -sS -X DELETE https://files.example.com/api/v1/shares/Ab3dE6gH -H "Authorization: Bearer $AGORA_TOKEN"
```

### 5.4 `DELETE /api/v1/auth/token`

Revokes the token that makes the call (the app's **Disconnect**). `204 No Content`; afterwards the token gets `401`.
Delete the token from the Keychain whatever the result (also on `401` or a network error).

```sh
curl -sS -X DELETE https://files.example.com/api/v1/auth/token -H "Authorization: Bearer $AGORA_TOKEN"
```

## 6. Errors and status codes

`401 Unauthorized` on any bearer endpoint:

| Situation | `WWW-Authenticate` | Body |
| --- | --- | --- |
| no `Authorization: Bearer agora_pat_...` header (including cookie-only requests) | `Bearer` | `{ "error": "An API token is required." }` |
| a token was sent but is unknown, revoked, expired or no longer valid for the account | `Bearer error="invalid_token"` | `{ "error": "The API token is invalid, revoked or expired; reconnect the app." }` |

On `401` with `invalid_token`, the app should delete its stored token and show "Reconnect".

Other general rules:

- `429 Too Many Requests`: wait for `Retry-After` seconds.
- `503 Service Unavailable` and `507 Insufficient Storage`: temporary; retry later with backoff.
- Error bodies are JSON with an `error` string meant for logs and short user messages (the token endpoint uses
  `error` codes plus `error_description`, see [section 3](#3-token-endpoint)). Branch on the status code, not on the
  message text.
- The API token never works outside `/api/v1`: other endpoints answer `401`/`403` JSON for it, never a redirect.

## 7. Token lifetime and revocation

A token has no fixed expiry. It stops working (the next call gets `401 invalid_token`) when:

- the app calls `DELETE /api/v1/auth/token` (Disconnect);
- the user clicks **Revoke** in Agora under Account settings > Connected apps;
- the user's **security stamp** changes: a confirmed password change, a password reset, a confirmed email change, or
  an administrator changing the user's role or enabled state. This disconnects every app of that user;
- the user is disabled or deleted;
- it has not been used for **180 days** (measured from the last use, or from the exchange if never used). The server
  records the last use at most every 15 minutes.

Revocation is immediate. The only way back is to connect again (section 2), which issues a new token; connecting again
does not revoke older tokens of other devices.

## 8. Client checklist

- Read the server URL from the user; call `/api/v1/me` after connecting to confirm the connection and show
  "Connected as <email>".
- Generate a new `code_verifier` and `state` for every connection attempt; never reuse them.
- Bind the callback listener to the loopback address only, accept one callback, time out after a few minutes.
- Use `directLinkDurations` and `maxFileSizeBytes` from `/me`; check the size before uploading.
- Upload with a filename ending in `.png` (or `.jpg`/`.jpeg` for JPEG).
- Map `401` to "Reconnect" (and drop the stored token), `429`/`503`/`507` to a retryable message, `413` to "too large".
- Keep the token only in the Keychain; never log it or the authorization code.
